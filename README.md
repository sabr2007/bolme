# Ночной поезд

**Интерактивный мистический мультфильм, которым управляют лицом через веб-камеру.**
Кейс Admit Hackathon 2026 «Motion: камера вместо джойстика», направление — свободное.

Ты просыпаешься в купе ночного поезда, который идёт через степь и не останавливается до рассвета. Проводнице не нужен билет — «я запомню ваше лицо». Куда ты посмотришь, кому улыбнёшься и закроешь ли глаза, когда погаснет свет, решает, какую из четырёх концовок ты увидишь.

## Как запустить

Нужны Node.js 20+ и браузер с веб-камерой (Chrome, Edge, Safari, Firefox; работает и на телефоне с фронтальной камерой).

```bash
npm install
npm run dev
# открыть http://localhost:5173 и нажать «Сесть в поезд»
```

Сборка: `npm run build` (статический сайт в `dist/`, сервер не нужен).

**Рабочая версия:** https://bolme.vercel.app

### Тесты

| Команда | Что проверяет |
|---|---|
| `npm test` | 22 unit-теста: правила жестов, подсказки режима «ошибка», удержание, граф сюжета (все 4 концовки достижимы) |
| `npx playwright test --project=journey` | весь путь пользователя на **виртуальном лице** (`?mock=1`): интро → проверка билета, где каждый жест сначала делается с ошибкой и должна появиться конкретная подсказка → 3 развилки → билет с итогами; плюс путь зрителя, который ничего не делает (ветки выбирает настроение). Замеряет время этапов и автоматически ищет наложения текста |
| `npm run e2e:fixture && npx playwright test --project=face` | распознавание на **реалистичном видео лица** как на веб-камере: калибровка, улыбка, нахмуриться, поворот головы |
| `npx playwright test --project=no-face` | камера без лица: приложение подсказывает «Не вижу лица» |

`?mock=1` — режим для автотестов: вместо камеры мимику задаёт скрипт через `window.__mockFace`, всё остальное (признаки, трекер жестов, подсказки, настроение) — настоящий код. `?debug=1` — панель с живыми значениями мимики и порогами жестов.

## Сценарий: от движения до результата

0. **Интро (~25 с, само листается).** Где ты, что фильм управляется лицом, пять жестов с иконками, что будет дальше.
1. **Проверка билета (обучение, ~45 с).** Проводница просит посмотреть на неё (калибровка нейтрального лица), улыбнуться, нахмуриться, посмотреть налево и направо, удивиться и закрыть глаза. Это обучение жестам внутри сюжета.
2. **Фильм (3–4 мин).** Три развилки, на каждой персонаж ждёт ответа лицом.
3. **Финал и «Твой билет».** Одна из 4 концовок; маршрут, профиль пассажира, кардиограмма страха, точность жестов, коллекция открытых концовок. Повтор — улыбкой.

Полный сценарий: [`docs/SCENARIO.md`](docs/SCENARIO.md). Архитектура: [`docs/ARCHITECTURE.md`](docs/ARCHITECTURE.md).

## Какие движения распознаются

| Жест | Как считывается | Действие в фильме |
|---|---|---|
| Поворот головы влево / вправо | угол поворота головы ≥ 18° от своего нейтрального положения | выбор пути: «на стук» (тамбур) или «на свет» (вагон-ресторан) |
| Искренняя улыбка | уголки губ вверх **и** прищур глаз (улыбка Дюшена) | довериться попутчику |
| Нахмуриться | обе брови опущены, без улыбки | отказать попутчику |
| Удивление | брови подняты **и** рот приоткрыт | окликнуть того, кто идёт по вагону |
| Закрыть глаза на 2 секунды | веки сомкнуты, удержание 2 с (моргание не считается) | спрятаться: экран гаснет, остаётся только звук |

Кроме жестов, приложение всё время считывает **настроение** (страх, радость, скука). Оно меняет звук (темп стука колёс, гул, сердцебиение), цвет кадра и реплики персонажей. Если зритель не ответил на развилке за 12 секунд, ветку выбирает настроение. Если зрителю скучно, Проводница стучит по «стеклу» экрана.

## Режим «ошибка» — как реализован

Каждый жест в [`src/gestures/definitions.ts`](src/gestures/definitions.ts) описан как **набор частей** с порогами (например, «улыбка» = губы + глаза). Трекер [`src/gestures/tracker.ts`](src/gestures/tracker.ts) каждый кадр оценивает, насколько зритель близок к жесту, и различает четыре вида ошибок:

1. **Почти получилось** — прогресс ≥ 45% дольше 0,7 с, но одна часть не выполнена. Подсказка называет именно её:
   - «Улыбка только губами — прищурь глаза, улыбнись по-настоящему»
   - «Сведи обе брови — сейчас хмурится только одна»
   - «Брови подняты — теперь приоткрой рот»
   - «Поверни голову влево сильнее — ещё примерно 7°» (считается сколько градусов не хватает)
2. **Типичная неправильная замена движения**: «Ты смотришь в сторону только глазами — поверни всю голову».
3. **Недостаточное удержание**: «Ты подсмотрел через 1,2 с — держи глаза закрытыми 2 секунды» (время измеряется).
4. **Проблемы с кадром**: «Не вижу лица», «Сядь ближе», «Сдвинься в центр», «Слишком темно — пусть экран освещает лицо».

Подсказка появляется только когда зритель явно пытается, не повторяется каждый кадр и не мешает спокойному просмотру. Пороги считаются относительно **нейтрального лица конкретного человека** (калибровка на старте), поэтому естественная полуулыбка или низкие брови не дают ложных срабатываний. Логика покрыта unit-тестами без камеры: `npm test`.

## Как сделан фильм

Кадры и клипы сгенерированы заранее, во время просмотра ничего не генерируется: просмотр бесплатный и без задержек.

- **Опорные кадры** — GPT Image (через Codex CLI), стиль стоп-моушн; персонажи сохраняются через референсы. Скрипт: [`tools/imagegen/codex_images.py`](tools/imagegen/codex_images.py).
- **Анимация** — Wan 2.2 image-to-video (14B, 4-шаговая LoRA) в ComfyUI на NVIDIA H100 (Brev). Скрипты: [`tools/comfy/`](tools/comfy).
- **Бесшовность**: у каждой развилки есть опорный кадр — петля ожидания начинается и заканчивается на нём, клипы-ответы с него начинаются (режим first-last-frame у Wan).
- **Звук** — процедурный, Web Audio, без аудиофайлов.

## Технологии

React + TypeScript + Vite, MediaPipe Face Landmarker (478 точек, 52 параметра мимики, матрица поворота головы) — всё в браузере, видео с камеры никуда не отправляется.
